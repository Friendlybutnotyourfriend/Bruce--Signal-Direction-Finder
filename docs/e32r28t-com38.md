# HUGINN E32R28T combined build

Target: QDtech E32R28T 2.8-inch ILI9341/XPT2046 board with the HaleHound
E07/E01 radio daughterboard. The user's current Windows port is **COM38**;
COM12 is obsolete for this installation.

This combines `agent/huginn-cbd-audio-fix` at `b1542d2` with
`agent/radio-control-centre-v1` at `c8a0c2d`. Merge resolution preserves
the newer BLE UI/audio implementation and pinned dependencies. It includes
BLE Hunter/Sniffer/session review, Antenna ID and controlled antenna
comparisons, and persistent CC1101/nRF24 Radio Control profiles.

## Board profile

Build with `python -m platformio run -e e32r28t-halehound`.
The profile reuses the E07/E01 support from the Fenrir implementation but
selects the E32R28T's ILI9341 display instead of Fenrir's ST7789. It does
not assume Fenrir's GPIO34 battery divider exists on the E32R28T.

| Signal | GPIO |
| --- | --- |
| Radio/SD SCK, MISO, MOSI | 18, 19, 23 |
| CC1101 CS, GDO0, GDO2 | 27, 22, 35 |
| E07 RX enable, TX enable | 0, 4 |
| nRF24 CS, CE | 26, 16 |
| SD CS | 5 |
| Display SCK, MOSI, MISO, CS, DC, backlight | 14, 13, 12, 15, 2, 21 |
| XPT2046 SCK, MOSI, MISO, CS, IRQ | 25, 32, 39, 33, 36 |

References checked 11 November 2026:
- https://github.com/bmorcelli/Launcher/issues/246
- https://github.com/JesseCHale/HaleHound-CYD#hardware-wiring

The E07 front end restricts SubGHz measurements to 425–450.5 MHz. Antenna
ID uses received signals; it does not independently measure antenna
resonance or replace a VNA. The comparison/profile tools remain included.

## Installation status

No device was read or flashed in the cloud workspace. Before installation,
the local operator must inspect COM38, back up its complete flash, verify
the installed partition layout, and choose the corresponding upload route.
This environment uses `custom_4Mb_full.csv`; it must not overwrite an
existing Launcher layout without deliberately arranging that migration.
Do not treat a successful source merge or host test as a successful firmware
build or hardware verification.

Host recon C++ checks and all 11 Python session tests passed during
integration. Hardware acceptance still requires display/touch, SD,
both radios, and receive-path checks on the actual unit.
